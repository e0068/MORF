# Установка

Модель — на холсте `модель-памяти.canvas`, подробности — в четырёх заметках `Claude/Docs/`. Здесь только то, чего нет ни там, ни там: как поставить и тексты команд.

| Файл | О чём |
|---|---|
| `docs/readme.md` | точка входа: что где лежит и с чего начинать |
| `модель-памяти.canvas` | устройство целиком, три блока и основание |
| `docs/наблюдения.md` | вход, ступени, оценки, вывод |
| `docs/факты.md` | третий выход, заметка, scope, доступ, возврат |
| `docs/правила.md` | две оси, связки за и против, трек-рекорд, жёсткость |
| `docs/основание.md` | архив, шкала времени, `/why`, настройки, ревизия |

Заметки объясняют, почему устроено именно так, и хранят отвергнутые варианты. Холст на них ссылается.

## Что из чего состоит

| Файл | Что делает |
|---|---|
| `archive-session.py` | хуки: регистрация сессии на входе, копия всех транскриптов на выходе |
| `score-memory.py` | оценки `S`, `R`, `t` в файлах памяти |
| `guard-archive.py` | блокирует запись и удаление в архиве |
| `config.json` | веса, единица шкалы и шаг ступеней; холст показывает его узлом-ссылкой |
| `levels.md` | ступени с горизонтами и лимитами; генерируется из конфига |
| `read-session.py` | читаемый разговор из архива, для `/why` |
| `build-index.py` | `TAGS.md` и `INDEX.md` — доступ к слою фактов |

## Быстрый путь

```bash
python3 install.py
```

Спросит, внутрь какой папки положить `Claude`. Найдёт корень хранилища по `.obsidian` и подстроит пути в скриптах и на холсте, если ставишь не в корень. Если папка `Claude` уже есть — вольётся в неё: недостающее создаст, совпадающее пропустит, а про отличающиеся файлы спросит отдельно, предлагая заменить, пропустить или отменить.

Руками останутся два текста ниже: хуки в `.claude/settings.json` и `CLAUDE.md` хранилища.

## Шаги вручную

**1. Папки.**

```bash
mkdir -p ~/Vault/Claude/Memory/{Scripts,Transcripts} ~/Vault/Claude/Facts
mkdir -p ~/Vault/.claude/commands
```

**2. Скрипты, холст, заметки.** Четыре скрипта и `config.json` — в `~/Vault/Claude/Memory/Scripts/`. Холст — в `~/Vault/Claude/Memory/`. Папку `Claude/Docs/` — в корень хранилища: холст вставляет заметки файловыми узлами по пути `docs/имя.md`, и путь должен совпасть. Затем:

```bash
chmod +x ~/Vault/Claude/Memory/Scripts/*.py
```

**3. Память первого проекта.** Замени `shader-lab` на своё:

```bash
cd ~/Vault/Claude/Memory
mkdir -p shader-lab
for f in day week month year dropped; do
  printf -- '---\nname: shader-lab-%s\nupdated: %s\n---\n\n' "$f" "$(date +%F)" > "shader-lab/$f.md"
done
printf -- '| id | дата | проект | о чём |\n|---|---|---|---|\n' > sessions.md
ls shader-lab
```

**4. Хуки.** Первый ведёт архив, второй его охраняет: запись и удаление в `Transcripts` блокируются, потому что наполняется он только копированием.

 `~/Vault/.claude/settings.json`, и тот же блок в каждый кодовый репозиторий:

```json
{
  "hooks": {
    "SessionStart": [{ "hooks": [{ "type": "command",
      "command": "python3 ~/Vault/Claude/Memory/Scripts/archive-session.py" }] }],
    "PreToolUse": [{ "hooks": [{ "type": "command",
      "command": "python3 ~/Vault/Claude/Memory/Scripts/guard-archive.py" }] }]
  }
}
```

**5. Доступ из кодовых сессий.** В `.claude/settings.json` репозитория:

```json
{ "permissions": { "additionalDirectories": ["~/Vault"] } }
```

Плюс строка в `CLAUDE.md` репозитория: `~/Vault` — чтение; заметки заводятся в сессии внутри хранилища.

**6. Срок хранения.** В `~/.claude/settings.json`: `"cleanupPeriodDays": 30`. Больше не нужно: постоянная копия делается на каждом `/handoff`, а своё хранилище Claude Code остаётся только источником для подметания оборванных сессий. Не `0` — по багу отключает саму запись транскриптов.

**7. Команды и `CLAUDE.md`** — тексты ниже.

**8. Проверка.**

```bash
cd ~/Vault && claude
```

Подтверди диалог доверия, иначе хуки не запустятся. Внутри: `/context` — должен быть `CLAUDE.md`; после выхода в `Claude/Memory/Transcripts/` появится папка сессии, а в `sessions.md` строка.

## `~/Vault/CLAUDE.md`

Инструкции по-английски: они грузятся каждую сессию и встают в одну форму со встроенными. Блок про язык обязателен — иначе агент ответит по-английски вслед за инструкцией.

```markdown
# Memory vault

## At session start

0. If the session start reported an unfinished stretch from a previous
   session, run `/handoff` for that stretch first, using the reference it
   gave you. Do it before anything else: the transcript is already archived,
   but nobody has turned it into observations yet.

1. Read for the current project: `Claude/Memory/<project>/L3.md`, `L2.md`, `L1.md`.
   Do not read the daily file — it is input for consolidation, not memory.
2. Read `Claude/Memory/levels.md` — it lists the levels, their horizons and
   line limits. The file is generated from `Scripts/config.json`; never edit it.
   If enough has accumulated since the last consolidation (the first level
   changed, or is approaching its limit), consolidate before starting work:
   - recompute scores: `python3 Claude/Memory/Scripts/score-memory.py`
   - work top down: fill `L2` from `L1` first, then `L1` from `L0`.
     Bottom up a line would climb two levels in one pass, and each level
     is meant to be a separate check.
   - group related lines into clusters
   - for each cluster, try to state an imperative:
     stated, enough weight  -> rule; hand it to the reviewer for a check
     stated, weight too low -> leave it, come back later
     cannot be stated       -> knowledge; write a note, carry the sources over
     weight decayed         -> `dropped.md`, with sources
   - promote a line one level up, displacing the weakest by `S`
   - report what changed in a single table
3. Check `Claude/Memory/audit.md`. Count the rows in `sessions.md` for this
   project after the `last` session id. Ten or more — run `/morf:audit`
   before starting work. Do not ask me whether to run it: I am not the timer.
4. Facts never arrive on their own: search `Claude/Memory/TAGS.md` -> `INDEX.md` -> 2-5 files.

An imperative produced by prefixing "do not" to an observation is a restatement,
not a rule. A real rule adds what the observation lacks: what to do instead,
and under which condition.

## Writing

- Memory line: `- hit:N use:N miss:N inverse:N text (s:...)`. Omit zero counters.
- A line without sources is invalid.
- Fact articles are about a phenomenon, not one fact per file.
  They live in `Claude/Facts`, carry front matter with `description`,
  `tags`, `scope`, `applied`, and link related phenomena with `[[...]]`.
  Before writing, look for an existing article and append to it.
  `description` answers "when would I need this".
- Do not invent tags outside `TAGS.md`; propose additions instead. A tag earns
  its place when at least two articles carry it — otherwise it narrows nothing.
- Never write to or delete from `Claude/Memory/Transcripts`. It is filled by
  copying from Claude Code's own history and by nothing else.
- When a phenomenon already has an article, append your source to the existing
  paragraph instead of writing a second one saying the same thing.
- A folder name states its relation to the parent, not a standalone label.
  Read a path bottom-up as a phrase before creating it: `Claude/Memory/Memory`
  would read as "memory of memory", which is not a thing — the level is spurious.
  `build-index.py` reports such paths.

## Never

- Do not touch `[S= R= t=]` by hand: the script writes them.
- Do not edit `TAGS.md`, `INDEX.md`, `sessions.md`: they are generated.
- Delete nothing. Displaced lines go to `dropped.md` with their sources.
- If a rule is violated often, propose making it a hook, but never move it
  yourself. A hook is a hard constraint imposed from outside: it closes off
  not only the violation but the view beyond it. After that you only see
  what it lets through.
- No passwords, tokens or credentials here.

## Language

Imperatives in English: these instructions, commands, rules, agent definitions.
Everything in the indicative — observations, knowledge notes, and your replies
to me — in Russian.
```

## `/handoff`

`~/Vault/.claude/commands/handoff.md`

```markdown
Reconcile what happened with what the system predicted.

1. Run `python3 Claude/Memory/Scripts/archive-session.py --handoff`.
   If you are recovering an unfinished stretch reported at session start,
   use that reference instead — the copy for it is already in the archive.
   It copies the transcript into the archive and prints a reference to the
   stretch written since the previous call: `s:260803-a41f#412-980`.
   Use that reference as the source for every line you write below.
   Fill the empty "о чём" column of the last row in `sessions.md`,
   three to five words, in Russian.

2. Expected outcomes are counters on existing lines. Add no new lines for them:
   `hit`  the prediction held
   `use`  the line took part in a decision (not "I read it" — "it changed what I did")
   `miss` the prediction did not hold
   `inverse` the opposite happened

   `inverse` also creates a new line: the opposite is itself unexpected.
   A refutation matters more than a new finding — never skip it for brevity.
   If a rule received a `inverse`, tell me immediately: it is suspended at once,
   waiting for the next session is not acceptable.

3. Unexpected outcomes become a new line in `Claude/Memory/<project>/L0.md`:
   `- hit:1 use:0 <what happened> (s:<id>)`
   Write it in Russian, in the indicative. An observation is what occurred.

4. If a conclusion about how to act formed during the work, do not discard it.
   Record the observation in the indicative, mark it `↑`, and attach the
   proposed rule wording on the line below, in English. Whether it becomes
   a rule is decided at the next session start: right now you are inside a
   fresh case and cannot weigh the evidence.

5. Invent nothing. If it did not happen in this session, it is not written.

Show me what you intend to write before writing it.
```

## `/why`

`~/Vault/.claude/commands/why.md`

```markdown
Take me back to the conversation a line came from.

The argument is a fragment of the wording: an observation, a note or a rule.

1. Find it across `Claude/Memory/`, including `dropped.md`, in knowledge notes
   and in rule files. Say where it lives.
2. For each source, run:
   `python3 Claude/Memory/Scripts/read-session.py <id> <keyword>`
3. Show the fragments in chronological order, with date and project from
   `sessions.md`. Do not skip the agents' reasoning — the answer is usually there.

If the file is missing from the archive, say so plainly and show what the index knows.
   The archive never expires. A missing file means the session was cut short
   before `SessionEnd`; the next `SessionStart` sweeps such transcripts in.

Finally, ask what to do with the line: keep it, restate it, or move it to `dropped.md`.
```

## `/morf:audit`

`~/Vault/.claude/commands/morf:audit.md`

Ревизия, а не механика: ничего не двигает и не решает, а показывает, верно ли настроены пороги. Запускается сама на каждой десятой сессии проекта — по той же шкале возможностей, что и всё остальное, а не по календарю.

```markdown
Audit the memory of the current project. Change nothing: report only.

1. Read `Claude/Memory/<project>/dropped.md` — entries displaced within the last
   hundred sessions of this project — and every line added to the ladder since
   the `last` session id recorded in `Claude/Memory/audit.md`.

2. Compare them by meaning, not by wording. Report pairs where something
   displaced earlier was written down again as a new observation.
   For each pair give both dates and both formulations.

   Two readings, and they call for different fixes:
   - same thing, same words -> displacement threshold is too low
   - same thing, different words -> the wording is unstable, and one
     observation is being recorded twice under two names

3. Count and report, without interpreting:
   - lines added, promoted, displaced since `last`, and over how many sessions
   - lines that became rules, and lines that became knowledge
   - lines sitting at the top level for over three months without an exit
   - whether `dropped.md` is growing faster than the ladder

4. Append to `Claude/Memory/audit.md`: the current session id as the new `last`,
   the counts, and the pairs found. Keep previous entries — this file is a history.

Say plainly if there is nothing to report. A quiet audit is a good result,
and inventing findings to look useful is the one failure mode here.
```

Файл `audit.md` заводится пустым:

```bash
printf -- 'last: none\n\n' > ~/Vault/Claude/Memory/audit.md
```

`last: none` означает «ревизий ещё не было»: первая пройдёт, когда у проекта наберётся десять сессий.

Календарного расписания намеренно нет. Месяц простоя и месяц ежедневной работы дают несопоставимый материал, а десять сессий — сопоставимый по определению.
